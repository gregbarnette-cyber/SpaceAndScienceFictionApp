Data model — two additive tables (not auto-seeded) + the generated spec

-- core/db.py (_migrate_schema — idempotent; existing DBs pick these up)
CREATE TABLE IF NOT EXISTS projects (
    project_id INTEGER PRIMARY KEY, name TEXT UNIQUE NOT NULL, description TEXT, created_date TEXT);
CREATE TABLE IF NOT EXISTS project_members (
    project_id INTEGER, star_name TEXT, note TEXT,
    source TEXT,                 -- 'looked_up' | 'generated'
    generated_seed INTEGER,      -- display convenience (generated only)
    generated_spec TEXT,         -- JSON: the FULL generate_system params → faithful re-creation
    added_date TEXT, PRIMARY KEY (project_id, star_name));

// generated_spec — a generated member reproduces byte-identically (R determinism):
{ "seed":88, "mode":"synthetic", "spectral_class":"K2V", "n_planets":6,
  "anchor_star":null, "constraints":null, "companion":null, "research_policy":"permissive" }
Storing the spec (not a frozen body) means a member never drifts from the generator, and a research_policy:"strict" member honestly records its dataset dependency. (Brainstorm stored only the bare seed — insufficient, since class/count are sampled and constraints/anchor change everything; see mockup §4 / D1.)
