Contract overview

Five new subcommands, each a thin verbatim wrapper over an already-shipped core/ function. Output is exactly what that function returns today, pretty-printed (json.dumps(result, indent=2, default=str)). Click any card — or a nav entry — to try it.

Key contract decision (see "Validation & exit codes"): N1–N4 wrap the older, non-self-validating equation/calculator functions. With no core changes, out-of-range numbers surface as {"error": str(e)} with a raw Python message ("math domain error" / "float division by zero") via query.py's top-level handler — exit 1. Only travel-time-solar emits curated error dicts. star-luminosity has no error path at all beyond argparse.

habitable-zone-sma

Kopparapu HZ boundaries plus the object's Seff at its orbit and a plain-language HZ-membership verdict. Complements the existing habitable-zone subcommand (which lacks the per-object Seff/verdict).

Plan details
  • equations.compute_habitable_zone_sma(teff, luminosity, sma) — wrapped verbatim, no network.
  • Output: {zones:[6×{zone_name,key,au,lm,seff}], planet_seff, verdict}.
  • planet_seff = (1/sma)²·luminosity; verdict compares it to the rv/rg/mg/em boundaries.
  • Validation: --sma 0 → exit 1 (division by zero); --luminosity < 0 → exit 1 (math domain).

star-luminosity

Stellar luminosity from radius and temperature — L = R²·(T/5778)⁴ (the opt-41 calc).

Plan details
  • equations.compute_star_luminosity(radius, temp) — wrapped verbatim, no network.
  • Output: {radius, temp, luminosity}.
  • Arg is --teff (naming parity with N1 / habitable-zone), mapped to the fn's temp parameter.
  • No error path: any float computes a number (radius is squared) — only argparse can reject input (non-numeric → exit 2).

brachistochrone-au

All three brachistochrone acceleration profiles for a given distance in AU (the opt-29 calc).

Plan details
  • calculators.compute_travel_time_system_au(accel_g, distance_au) — wrapped verbatim, no network.
  • Output: {accel_g, distance_au, distance_lm, profiles:[3×{label,hours,travel_time_str,max_vel}]}.
  • Profiles: ① continuous-to-halfway · ② accel¼/coast½/decel¼ · ③ accel-to-3%c/coast/decel.
  • Validation: --accel-g 0 → exit 1 (division by zero); negative distance/accel → exit 1 (math domain).

travel-time-solar LIVE JPL HORIZONS

Brachistochrone travel time between two solar-system bodies at a departure epoch (the opt-22 calc). The only network-bound subcommand added this phase — it queries JPL Horizons for both bodies' heliocentric positions, so the JSON below is a canned sample (not computed in your browser).

Plan details
  • calculators.compute_travel_time_solar_objects(origin, destination, accel_g, v_cap_pct=3.0, departure_date=None).
  • --v-cap-pct defaults to 3.0; --date is ISO YYYY-MM-DD (default: today) → maps to departure_date.
  • progress_callback is GUI-only and is never passed — it stays at its None default.
  • Output: {origin, destination, accel_g, distance_au, distance_lm, v_cap_pct, departure_date, profiles, …} or curated {"error": …} (ambiguous Horizons name, same-object, or network failure).
  • Result also carries origin_xyz / dest_xyz / planet_positions / origin_id / dest_id — JSON consumers may ignore these.

Validation & exit codes

Standard query.py contract: argparse errors exit 2 (stderr); a result dict with an "error" key exits 1; success exits 0. The nuance this phase documents honestly: N1–N4 wrap non-validating legacy functions, so their out-of-range errors are raw exception messages, not curated sentences.

Input class habitable-zone-smastar-luminosity brachistochrone-au/lmtravel-time-solar
Valid exit 0 · resultexit 0 · result exit 0 · resultexit 0 · result
Missing / non-numeric arg exit 2 · stderrexit 2 · stderr exit 2 · stderrexit 2 · stderr
Zero where it divides exit 1 · --sma 0 → "float division by zero" — (no division) exit 1 · --accel-g 0 → "float division by zero" exit 1 · --accel-g 0 (after network)
Negative → sqrt domain exit 1 · --luminosity -1 → "math domain error" exit 0 (radius² ⇒ valid number) exit 1 · negative au/lm/accel → "math domain error" n/a
Semantic (network / ambiguous / self) n/an/an/a exit 1 · curated {"error": …} (disambiguation / same-object / network-down)
Why not add validation? Phase N's hard constraint is no core/ changes, and the verbatim-wrapper property means we don't add per-command checks in query.py either. This matches the existing blessed precedent: tests/test_equations.py::test_bad_input_raises already documents that compute_habitable_zone(5778, -1.0) raises and query.py's top-level handler turns it into {"error": …}. The real behavior is documented in docs/integration.md so callers aren't surprised.
