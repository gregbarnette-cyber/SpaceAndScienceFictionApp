The one real change to weigh. The current concentric Rings diagram draws only the zone structure — it has never plotted the system's planets. The Strip adds planet markers placed by semi-major axis (green inside the optimistic HZ, blue outside). So Strip is not merely "the same picture, sideways" — it surfaces where each planet actually falls relative to the zones. Rings is proposed to stay planet-free and byte-identical (protecting any golden output); Strip is the place the planets show up. Confirm that split below.

Rings vs Strip — the same star, both ways

Sol shown in both. Rings answers "how big are the zones?"; Strip answers "which planets land in them, and by how much?" on a compressed √AU axis where the inner planets don't collapse onto the star.

Rings — today's diagram (unchanged)

Concentric Kopparapu zones, hot (inner, red) → cold (outer, blue). Click-to-explain + EEID/snow-line markers stay exactly as they are.

Strip — new opt-in view

Optimistic (light) + conservative (dark) HZ bands on a √AU rule, with each planet dropped in at its orbit. Green = inside the optimistic HZ.

How it's built

Additive only. The existing make_hz_canvas (Rings) is not touched, so every current caller and any golden output is unchanged.

1
core.viz — prepare_hz_strip(teff, lum, planets=None) Reuses the same Kopparapu zone boundaries as prepare_hz_diagram; returns the optimistic & conservative band edges plus a normalized planet list [{name, au, in_hz}].
2
plot_helpers — make_hz_strip_canvas(...) Draws the √AU strip in the app's dark-navy Star-Chart palette: two HZ bands, AU ticks, planet dots (green in-HZ / blue out), hover + click-to-info parity with the other diagrams.
3
A shared toggle wrapper — wrap_hz_with_toggle(...) Returns one QWidget: the Rings | Strip segmented control over a QStackedWidget. Each HZ-tab builder (_make_hz_tab, the Star-Regions and HWC builders) calls it instead of adding the bare rings canvas — so the control appears identically everywhere.
4
Tests Unit-test prepare_hz_strip (band edges + in_hz flags vs known anchors) and a headless canvas/​toggle smoke test, matching the OEC test pattern.
